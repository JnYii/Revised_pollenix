# 京粉报：第二份完整原算法＋第一份公园界面

版本：2026-09-19-original-second-5.0。

计算以用户第二份文件为唯一基线。app.py中标记为“ORIGINAL SECOND ALGORITHM”的部分，是第二份原文件第1—960行的逐字复制：数据类、全部计算函数、所有系数、季节参数、条件分支、分级和建议都没有改动。公众界面沿用紧凑卡片、绿色仪表、九列公园参数表和侧栏公园切换。

## 启动与更新

```sh
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

主程序仍为单文件app.py。更新时替换正在运行的旧app.py并重启；不要启动之前解压目录中的旧版本。

## 输入怎样对应原文件

- 公园选择继续使用第一份数据：北京动物园有效绿地40ha；颐和园116.32ha。该面积直接传给第二份的green_area。
- 背景花粉、风速、湿度、降雨、日照、温度、PM2.5、UV与连续晴天的默认值及输入范围全部恢复为第二份原侧栏值。原先缺少的UV与连续晴天输入已补回。
- 刺柏、杨树、柳树密度初值继续为第二份的2、3、2棵/ha，没有重新估计，也没有把其他树种自动并入刺柏。它们不是本次重新调查得到的公园密度；可以在开发者模式填入掌握的输入。
- 蒿属与草本密度直接由第二份的面积估算函数产生。没有新增覆盖率、株高、花期时长或草本放大倍率。
- 原第二份的完整初始场景使用120ha；在开发者模式将有效绿地改为120ha，即可复现该初始面积。其他默认输入已相同。

## 开发者模式

每园可选择“使用原版默认值”或“填写具体数值”。可填写的量严格限于原模型已有输入：有效绿地面积，以及刺柏、杨树、柳树密度。点击保存后生效；返回公众页保留当前日期和天气。切回默认值后，之前填写的数值仍保存。

新配置为app.py旁的original_inputs.json，可用BJ_POLLENIX_ORIGINAL_CONFIG指定位置。包内没有预置测试配置。

原第二份没有手动草本密度、覆盖率、株高或独立藜科接口，因此当前严格复现版不增设这些计算。旧herb_settings.json不会被读取、转换或覆盖；之前填写的记录仍在原文件内。独立藜科模型不属于第二份原算法，这一版未自行补参数。

## 页面数值

综合风险、等级、建议和贡献图直接显示原calculate_risk返回值。贡献图使用原文件的五项“过敏源小分”，随所选日期变化。

I_GZA、I_GZA*与原九列植被表保留为第一份公园资料展示，不再参与第二份的总分。指标名称按实际返回内容显示，避免把原“局部花粉暴露”误写成未经植被增强的背景评分。

日期严格沿用原来的“月份＋(日号－1)/30”及原季节函数。本版没有擅自修正月底、改底值或放大曲线。相同输入下，本版应与原第二份完全相同；如果原式在某些日期结果相同或舍入后相近，本版也原样保留。

## 验证

48项测试通过，包含1000组输入全结果对照、两公园平年/闰年逐日对照、原条件阈值、页面数字卡/仪表/贡献图，以及数据保存。原代码与新版相同输入的全部返回结果完全一致，最大差值为0。详情见[TEST_REPORT.md](TEST_REPORT.md)。
